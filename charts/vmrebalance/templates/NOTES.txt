Started the Job {{ $job }}, which migrates {{ .Values.from }} → {{ .Values.to }}.

Follow it:
  kubectl -n {{ .Release.Namespace }} logs -f job/{{ $job }}

Progress (state in the ConfigMap vmrebalance.{{ .Values.from }}.{{ .Values.to }}):
  vmrebalance status -n {{ .Release.Namespace }} --from {{ .Values.from }} --to {{ .Values.to }}

The Job runs preflight, the backfill, verify and the catch-ups. It waits while preflight fails, for example until
{{ .Values.to }} exists and receives dual writes. Once it logs "green is ready for the cutover" (and the metric
vmrebalance_phase{phase="ready"} is 1), switch the read and write aliases to {{ .Values.to }}. The Job notices the
cutover, runs the final sync and completes. Then keep {{ .Values.from }} for a few days so you can roll back, and
delete it.

An upgrade removes the running Job and starts a new one, which continues where it stopped.
